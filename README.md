> ⚠️ **IMPORTANT REGULATORY & ACADEMIC DISCLAIMER**:  
> This system is strictly an **academic decision-support prototype**, **NOT an official flood early warning system**. It forecasts **modelled GloFAS river discharge (m³/s)** and does not simulate localized river bathymetry, sluice/dam reservoir gate releases, storm surge tides, or urban drainage blockages. Under no circumstances should this system be used for official civil protection or emergency evacuation orders. Always follow the official releases issued by the **Central Water Commission (CWC)**, the **India Meteorological Department (IMD)**, and the **Tamil Nadu State Disaster Management Authority (TNSDMA)**.

## 1. Project Overview & Scientific Scope
ClimateShield AI v2 forecasts future river flow (modelled discharge in m³/s) at monitored stations across Tamil Nadu river basins for horizons $h \in \{1, 3, 7\}$ days ahead.

### Standing Honesty Rules
1. **No hardcoded numbers**: Every metric, interval coverage, latency benchmark, and evaluation score is dynamically generated by code and read from `reports/*.json|csv`.
2. **Modelled Discharge Target**: The predicted target is modelled GloFAS river discharge (m³/s), not physical gauge stage height.
3. **Regulatory Notice**: Decoupled from statutory flood warnings; thresholds are historical statistical percentiles ($p_{50}, p_{75}, p_{90}$).
4. **Latency Honesty**: The word "real-time" is strictly qualified by measured ingest-to-display numbers from [`reports/latency.json`](reports/latency.json) (**Median: 6.07 ms | p95: 14.79 ms**).
5. **Statistical Significance Gating**: Models can only claim to beat persistence if backed by the Diebold-Mariano test with Harvey-Leybourne-Newbold correction ($p < 0.05$).
6. **Data Attribution**: Precipitation and river discharge data courtesy of [Open-Meteo.com](https://open-meteo.com) under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).

## 3. Quick Start & Execution

### Installation
```bash
git clone https://github.com/your-username/flood-prediction.git
cd flood-prediction

python -m venv .venv
# Windows:
.venv\Scripts\Activate.ps1
# Linux / macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

### Run Tests
Execute the full test suite (194 tests):
```bash
pytest -v
```

### Full Pipeline Training Across All Stations
Run data validation, sanity checks, cleaning, alignment, feature extraction, chronological splitting, model training across horizons 1/3/7, conformal interval calibration, and benchmark reports:
```bash
# Train all stations
python -m src.train --all-stations

# Train a single station
python -m src.train --station TN_CAU_TRICHY
```

### Automated Retraining with Validation RMSE Gate
Retrain a station with new data, ensuring that model artifacts on disk are updated **only** if the newly trained model beats or matches the currently deployed model's validation RMSE ($\text{RMSE}_{\text{new}} \le \text{RMSE}_{\text{current}} \times 1.001$):
```bash
python -m src.retrain --station TN_CAU_TRICHY
```

### Central Water Commission (CWC) / India-WRIS In-Situ Gauge Data Upload & Ingestion
External ground-truth river gauge observations from the Central Water Commission (CWC) or India-WRIS can be uploaded and aligned with precipitation records for physical calibration and retraining:
1. **Schema Requirement**:
   - `timestamp` (or `date`): ISO-formatted date string or datetime. If timezone-naive, Indian Standard Time (`Asia/Kolkata`, UTC+05:30) is validated and assumed.
   - `station_id`: String identifier matching monitored station (e.g. `TN_CAU_TRICHY`).
   - `value`: Numerical gauge observation (water level in meters or discharge in m³/s).
   - `unit`: Unit of measurement (`m`, `m3/s`, `cumec`, `cm`, `cusec`). Values are automatically converted to standard SI (`m` or `m³/s`).
2. **Uploading & Retraining**:
   - In the interactive dashboard, open **Tab 9 (Data Quality & Sanity)** and expand **Upload CWC / India-WRIS In-Situ Gauge Data**.
   - Validate and align the gauge dataset, which writes to `data/processed/<station_id>_gauge_aligned.csv`.
   - Retrain models against ground-truth gauge discharge:
     ```bash
     python -m src.train --station <station_id>
     ```

### Launch Interactive Dashboard
Launch the unified Streamlit application:
```bash
streamlit run src/dashboard/app.py
```

## 4. Key Generated Reports & Artifacts

All benchmark outputs, coverage metrics, and audit logs are dynamically written to `reports/`:
- [`reports/model_scores_all.csv`](reports/model_scores_all.csv): Comprehensive evaluation matrix across all stations, horizons, and models (MAE, RMSE, R2, NSE, peak error, peak timing error, missed events, false alarms, interval coverage, train time, beats persistence, beats all baselines).
- [`reports/training_coverage.csv`](reports/training_coverage.csv): 270-cell coverage matrix (station $\times$ horizon $\times$ model) with training status (`trained`, `skipped`, `insufficient_data`) and diagnostic notes.
- [`reports/feature_ablation.csv`](reports/feature_ablation.csv): Feature-group ablation study demonstrating impact of rainfall intensity, discharge dynamics, and calendar features.
- [`reports/target_transforms.json`](reports/target_transforms.json): Empirical validation comparing raw discharge target against $\log(1 + y)$ transformation.
- [`reports/retrain_log.jsonl`](reports/retrain_log.jsonl): Audit trail of all retraining runs and validation quality gating decisions.
- [`reports/training_log.jsonl`](reports/training_log.jsonl): Audit log of model training iterations, data hashes, durations, and metrics.
- [`reports/data_sanity_<station_id>.json`](reports/): Station-by-station data health and grid-snap sanity reports.

## 5. Dashboard Features & Design System
- **Centralized CSS Design System** (`src/dashboard/styles.py`): Deep navy theme, accessible typography, and uniform KPI cards.
- **Top 5 KPI Cards**:
  1. *Risk Category* (Statistical percentile threshold, not CWC level)
  2. *Expected Peak / Forecast Flow* (+1d, +3d, or +7d horizon)
  3. *Latest Observed Flow* (Modelled GloFAS discharge)
  4. *90% Conformal Prediction Interval* (Nominal 90%, with measured empirical test coverage)
  5. *Confidence & Data Freshness* (Population Stability Index drift check & staleness monitor)
- **10 Core Navigation Tabs**:
  1. *Overview*: Basin metadata & auto-centered OpenStreetMap.
  2. *Forecast*: Interactive fan chart, plain-language hydrologic drivers, and rainfall what-if simulator.
  3. *All Stations*: Cross-basin status table with best-model indicators.
  4. *ML Model Comparison*: Benchmarking table with tick marks, RMSE comparison bar chart, and feature ablation study.
  5. *Training Status*: Coverage matrix with status pills and retrain commands.
  6. *Historical Backtest*: Replay of past high-flow events and warning lead time evaluation.
  7. *Rainfall Risk*: IMD meteorological indicators strictly side-by-side with GloFAS hydrologic discharge categories.
  8. *Verification & Drift*: Forward verification enforcement ($n \ge 30$) and input feature drift monitoring.
  9. *Data Quality*: Station sanity checks, missing data handling, and grid-snap coordinates.
  10. *About & Limitations*: Regulatory notices and academic limitations.
